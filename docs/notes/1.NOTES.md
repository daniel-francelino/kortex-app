# Módulo Notas

O módulo **Notas** é o espaço de conhecimento do Kortex: uma mistura de **Obsidian** (vínculos bidirecionais entre notas, grafo de conhecimento) com **Notion** (editor de blocos rico, arrastar-e-soltar, colunas, slash menu). É onde o usuário registra estudos, ideias, pesquisas e anotações de livros, conectando o conteúdo por meio de wikilinks e menções.

Rota: `/app/notes` (`app/pages/app/notes/index.vue`, `ssr: false`).

> Este documento descreve o estado **atual** da implementação, incluindo partes que existem no código mas ainda não estão acessíveis pela interface (sinalizadas explicitamente). Ver também `docs/NOTES.md` para a lista de bugs/melhorias em aberto, `docs/ANALISE_EDITOR_MERCADO.md` para o roadmap comparado ao mercado, e `docs/PLANO_COMPARTILHAMENTO_E_OFFLINE.md` para as especificações de compartilhamento público e modo offline (ainda não implementadas).

## 1. Visão geral da tela

A página é um painel (`UDashboardPanel`, id `notes`) dividido em duas áreas:

- **Barra lateral esquerda** (redimensionável, 180–520px, largura persistida em `localStorage` via `useStorage('notes-sidebar-width', 288)`):
  - Botão **Nova nota** (`i-lucide-square-pen`) — cria uma nota "Untitled" instantaneamente (sem modal).
  - Botão **Nova pasta** (`i-lucide-folder-plus`) — cria uma pasta "Nova pasta" instantaneamente.
  - Dropdown de **ordenação**: Mais recentes / Mais antigas / A-Z / **Personalizado** (`notes-sort-mode`, persistido em `localStorage`).
  - Botão **Buscar** — abre o `SearchDialog`.
  - Alternador **Editor ⇄ Grafo** (`i-lucide-file-text` / `i-lucide-network`).
  - Botão **Lixeira** (`i-lucide-trash-2`) — abre a visão de itens excluídos (ver seção 2.1).
  - Lista de notas e pastas (`NotesList`).
- **Área principal**: o editor da nota selecionada (`NoteEditor`), a visualização em grafo (`GraphView`) ou a Lixeira (`NotesTrashView`), conforme o alternador acima — a troca entre elas tem uma transição de crossfade (`motion-v`).

A nota selecionada é sincronizada com a URL via query param (`?note=<id>`, atualizado com `router.replace` — não empilha entrada de histórico do navegador a cada troca) — dá para compartilhar um link direto e recarregar a página do zero numa nota específica. Se a URL também tiver um hash `#block-<blockId>`, a página rola até esse bloco assim que o conteúdo da nota termina de carregar (poll curto até o elemento existir no DOM, já que a renderização do editor é assíncrona). O botão "voltar" do navegador continua não navegando entre notas: esse gesto é coberto pela pilha própria de navegação da página (`noteHistory`/`historyIndex`, ver abaixo), não pelo histórico do navegador.

### Histórico de navegação interno

A página mantém uma pilha própria de navegação (`noteHistory` + `historyIndex`) com botões conceituais de avançar/voltar entre notas visitadas. Antes de trocar de nota, qualquer alteração pendente é salva automaticamente (`saveCurrentNoteIfNeeded`), inclusive ao sair da rota (`onBeforeRouteLeave`).

### Fonte de dados: paginada vs. completa

Quando existe pelo menos uma pasta, a árvore da barra lateral passa a usar sempre a lista completa de notas (`allNotes`, até 500 itens, sem paginação) em vez da lista paginada — isso evita que a árvore de pastas e a lista "raiz" mostrem dados divergentes. A paginação (`UPagination`) só aparece quando **não há nenhuma pasta** criada.

### Funcionalidades presentes no código mas não expostas na tela hoje

- **Outline (sumário de títulos)**: a página já calcula os headings (H1–H3) da nota atual a partir do conteúdo Tiptap, mas esse sumário não é renderizado em nenhum lugar da interface atual.
- **Filtro por tipo de nota**: existe estado (`filters.type`) e as opções (`noteTypeOptions`), mas não há seletor visível na tela para filtrar por tipo.

## 2. Lista de notas e pastas (`NotesList.vue`)

Renderiza uma **lista única indentada** misturando pastas e notas:

- Se existir pelo menos uma pasta, o componente monta uma árvore recursiva (pastas com subpastas e notas aninhadas, indentadas por profundidade) e as notas sem pasta aparecem na raiz.
- Se não existir nenhuma pasta, cai para uma lista simples paginada de notas.

**Alinhamento e espaço**: pastas e notas compartilham a mesma largura reservada para o chevron de expandir (nas notas, esse espaço é um spaçador invisível do mesmo tamanho), garantindo que os ícones fiquem alinhados verticalmente no mesmo nível de profundidade. O recuo por nível é `0.25rem` de base + `0.75rem` por nível de profundidade (compacto o suficiente para não desperdiçar espaço horizontal em árvores com vários níveis de subpastas).

**Pastas**:
- Expansíveis/recolhíveis; ícone de pasta âmbar e um chevron que **gira** (animação de rotação, não troca de ícone) ao expandir/recolher.
- **Estado expandido/recolhido é persistido no banco** (`note_folders.is_expanded`), não em `localStorage` — ao contrário de outras preferências de UI do módulo (largura da sidebar, modo de ordenação), esse estado é parte do dado da própria pasta e por isso fica consistente entre dispositivos/navegadores do mesmo usuário. A escrita no backend é debounced (400ms) por pasta, mas o clique reflete instantaneamente na UI independente disso.
- Renomeação inline: lápis no menu, item "Renomear" do menu de contexto, **ou duplo-clique direto na linha** — nos três casos o input recebe foco garantido (mesmo competindo com o comportamento padrão de menus suspensos de devolver o foco ao botão que os abriu).
- Arrastáveis entre si **apenas no modo de ordenação "Personalizado"** (ver abaixo) — nos demais modos, pastas não são arrastáveis e ficam sempre em ordem alfabética.

**Notas**:
- Mostram o emoji customizado (`icon`) se definido; caso contrário, o ícone/cor padrão do tipo (`NOTE_TYPE_META`).
- Renomeação inline (lápis, menu de contexto, ou duplo-clique).
- Notas fixadas mostram um ícone de pin (com tooltip "Nota fixada") ao lado do título, que aparece/desaparece com uma pequena animação ao fixar/desfixar.

### Ordenação

Quatro modos, selecionáveis no dropdown do topo:

- **Mais recentes / Mais antigas / A-Z**: pastas sempre em bloco alfabético, listadas antes das notas (comportamento "pastas primeiro" convencional). Notas fixadas sempre no topo das notas do seu nível, sub-ordenadas pelo mesmo critério do modo ativo (data de atualização ou alfabética).
- **Personalizado**: pastas e notas do mesmo nível são combinadas numa **única ordem**, definida por `position` (um número de ponto flutuante por item) e reordenável por arrastar-e-soltar — nesse modo dá para intercalar livremente pasta/nota/pasta, ao contrário dos outros três modos onde pastas e notas ficam sempre em blocos separados.

### Notas fixadas — regra de prioridade

Uma nota fixada **sempre aparece no topo do seu nível**, com prioridade acima de qualquer outro critério de ordenação — inclusive acima de pastas no modo Personalizado (pin tem prioridade sobre `position`). A sub-ordenação entre notas fixadas entre si muda conforme o modo:

| Modo de ordenação | Critério entre notas fixadas |
| --- | --- |
| A-Z | Alfabética |
| Mais recentes / Mais antigas | Data de atualização |
| Personalizado | **Data em que foi fixada** — quem fixou primeiro aparece primeiro |

Notas fixadas **não podem ser arrastadas** (o atributo `draggable` fica desativado nelas) e **não servem de alvo válido** para reordenar outros itens ao redor delas — como a posição de uma nota fixada não é controlada manualmente (é sempre "topo do nível"), ela fica de fora do cálculo de posição entre vizinhos.

### Drag-and-drop

Usa HTML5 DnD nativo com tipos MIME próprios (`application/x-notes-note-id` para notas, `application/x-notes-folder-id` para pastas, esta última só ativa no modo Personalizado).

- **Mover para dentro de uma pasta**: soltar uma nota em qualquer lugar da linha da pasta (fora do modo Personalizado) — ou na faixa central da linha, no modo Personalizado (ver zonas abaixo) — move a nota pra lá (`move-to-folder`), sem posição específica.
- **Reordenar (só no modo Personalizado)**: soltar uma nota ou pasta perto da borda superior/inferior de outra linha (nota ou pasta, de qualquer tipo) reposiciona o item arrastado como vizinho ali, recalculando sua `position` como a média entre as posições dos vizinhos adjacentes (indexação fracionária — não precisa renumerar a lista inteira a cada arraste). Arrastar de fora para dentro de uma pasta, numa posição específica, move **e** posiciona numa única operação.
- **Três zonas nas linhas de pasta** (modo Personalizado): uma faixa fina (8px) no topo ou no fim da linha = "reordenar como vizinho da pasta"; o meio da linha = "mover pra dentro da pasta" — o mesmo padrão usado por exploradores de arquivo como o do VS Code.
- **Pastas só reordenam entre irmãs do mesmo pai** — esse gesto não reparenta uma pasta (não move pra dentro/fora de outra pasta via drag).
- **Indicador visual animado**: uma barra fina que cresce (`scaleX`, `motion-v`) na borda de cima/baixo da linha-alvo, substituindo o antigo indicador de borda estática.
- **Auto-scroll**: arrastar perto do topo ou do fim da lista (quando ela é maior que a área visível) faz a lista rolar sozinha, com velocidade proporcional à proximidade da borda; para assim que o cursor se afasta da borda, ou quando o drag termina/é cancelado.
- **Animações de linha** (`motion-v`): cada linha anima entrada (fade + slide), saída (fade + colapso de altura) e reposicionamento suave (layout/FLIP) quando a ordem muda; a linha em arrasto ativo fica com opacidade e escala reduzidas como feedback visual do estado "sendo arrastada".

**Menus de contexto** (clique direito ou botão "⋮" ao passar o mouse), com as mesmas ações nos dois:
- **Pasta**: Nova nota, Nova pasta (subpasta), Renomear, Excluir pasta.
- **Nota**: Renomear, Fixar/Desafixar, Duplicar, Excluir.
- **Área raiz vazia**: Nova nota, Nova pasta.

**Exclusão de pasta**: é sempre **em cascata completa** — exclui recursivamente todas as subpastas e todas as notas dentro delas (não deixa mais notas "órfãs" na raiz como antes). Uma confirmação é exibida antes, informando quantas notas e subpastas serão afetadas (calculado localmente, sem chamada extra ao servidor). Desde a Parte 8 do `docs/PLANO_EDITOR_P1.md`, excluir uma nota ou pasta é **reversível** — ver seção 2.1.

### 2.1 Lixeira (soft delete) — `NotesTrashView.vue`

Excluir uma nota ou pasta não a remove de verdade: o backend marca `deleted_at = now()` (nota ou pasta, e recursivamente todas as subpastas/notas descendentes no caso de uma pasta) em vez de apagar a linha. Itens excluídos somem de toda leitura normal (listagem, busca, grafo, link público, "compartilhadas comigo") mas continuam recuperáveis.

- **Acesso**: botão "Lixeira" (`i-lucide-trash-2`) na barra de ferramentas da sidebar, ao lado do alternador Editor/Grafo — troca a área principal para `NotesTrashView.vue`.
- **Lista**: notas e pastas excluídas juntas (sem árvore), mais recentemente excluído primeiro, cada linha com ícone, título, "excluído há X" (`date-fns`, locale pt-BR) e dois botões: **Restaurar** e **Excluir permanentemente** (este último pede confirmação — é literal, sem outra rede de segurança depois).
- **Restaurar nota**: limpa `deleted_at`; se a pasta original também estiver na lixeira, a nota volta para a raiz em vez de ficar presa numa pasta invisível.
- **Restaurar pasta**: limpa `deleted_at` da pasta **e de todos os descendentes** (restauração em cascata, espelhando a exclusão); mesma regra de "volta pra raiz" se o pai também estiver excluído.
- **Exclusão permanente**: remove a linha de verdade (hard delete) — só é possível a partir da lixeira, tanto na UI quanto no backend (os endpoints `.../permanent` recusam operar em algo que não esteja com `deleted_at` preenchido). Para pastas, a cascata (`ON DELETE CASCADE`) continua removendo subpastas/notas de verdade.
- **Purga automática**: endpoint `POST /api/notes/trash/purge` remove permanentemente qualquer coisa na lixeira há mais de 30 dias — protegido por segredo compartilhado (`x-cron-secret` contra `runtimeConfig.cronSecret`, mesmo padrão de `server/api/habits/cron-skip.post.ts`). **O agendamento em si (cron) não está neste repositório** — precisa ser configurado manualmente por fora, como o cron de hábitos já precisou ser.

## 3. Criação de nota (`NoteCreateModal.vue`)

Existe um modal completo de criação com três campos — **Título**, **Tipo** (select com os 5 tipos de nota) e **Conteúdo (opcional)** em `textarea` de texto puro, com dica de que `[[Nome da Nota]]` vincula e `#tag` categoriza.

⚠️ **Estado atual**: os botões "+" da barra lateral **não abrem esse modal** — eles chamam a criação rápida diretamente (`onQuickCreateNote`), gerando uma nota chamada "Untitled" sem passar por título/tipo/conteúdo. O modal parece não ter nenhum gatilho visível na tela hoje. Além disso, mesmo que fosse aberto, o texto digitado no `textarea` (incluindo `[[...]]` e `#tag`) **não é convertido** em wikilinks/tags reais — é salvo como texto literal, pois o editor real (Tiptap) é quem interpreta essa sintaxe.

A atribuição de pasta na criação não passa por esse modal: acontece via drag-and-drop na lista, ou usando "Nova nota" no menu de contexto de uma pasta específica — nesse caso, a pasta escolhida é persistida corretamente no momento da criação, e se a pasta (ou algum ancestral dela) estiver recolhida, a árvore expande automaticamente a cadeia de pastas até a nota nova ficar visível.

## 4. O editor de blocos (estilo Notion)

Cadeia de componentes: `NoteEditor.vue` (moldura específica da nota: breadcrumb, título, ícone, tipo, status de salvamento) → `EditorNotionStyleEditor` / `NotionStyleEditor.vue` (wrapper genérico do Tiptap, reutilizável — também usado pelo módulo Diário) → extensões/nós definidos em `useNotionEditor.ts`.

> Uma análise comparada com o que Notion/Obsidian oferecem (e o que a comunidade desses produtos pede e ainda não tem) está em `docs/ANALISE_EDITOR_MERCADO.md`, com roadmap priorizado.

### 4.1 Tipos de bloco suportados

Do `StarterKit` (com ajustes): parágrafo, títulos H1–H3, lista com marcadores, lista numerada, citação, bloco de código **com realce de sintaxe** (`@tiptap/extension-code-block-lowlight` + `lowlight`, subset `common` de ~35 linguagens; seletor de linguagem — dropdown curado com ~15 opções — no canto superior direito do bloco, visível no hover/edição), divisor (`hr`), quebra de linha, e marcas de texto (negrito, itálico, tachado, código inline).

Blocos/nós customizados adicionados por cima:

| Bloco | Descrição |
| --- | --- |
| **Lista de tarefas** | Checkboxes aninháveis (`taskList`/`taskItem`) |
| **Callout** | Bloco de destaque com ícone emoji configurável (padrão 💡) |
| **Imagem** | Bloco arrastável com largura ajustável, legenda e opção de substituir arquivo |
| **Arquivo** | Anexo genérico renderizado como cartão com link de download |
| **Menção (`@`)** | Nó inline que referencia uma nota (ou texto livre) |
| **Emoji** | Nó inline de emoji |
| **Preview de link** | Cartão rico com título/descrição/imagem obtidos via Open Graph |
| **Wikilink (`[[...]]`)** | Nó inline de link entre notas |
| **Colunas** | Layout multi-coluna (2 ou mais colunas lado a lado) |
| **Tabela** | Linhas/colunas redimensionáveis, com cabeçalho |
| **Alternador (toggle)** | Bloco recolhível — primeiro filho é o resumo, o resto é o corpo escondido via CSS quando fechado (preservado no documento, não removido) |

Formatação de texto adicional: alinhamento (esquerda/centro/direita/justificado, em parágrafos e títulos), sublinhado, links com auto-detecção de URL, **cor de texto e destaque (highlight)** — paleta fixa de 9 cores (padrão Notion), aplicada via `@tiptap/extension-color`/`@tiptap/extension-highlight`/`@tiptap/extension-text-style`, com view própria na bubble menu (ver 4.6).

Cada bloco de nível superior recebe um `blockId` estável (UUID), usado tanto pelo sistema de arrastar-e-soltar quanto pela ação **"Copiar link do bloco"** (menu da alça de arraste, ver 4.3) — copia `${origin}${pathname}?note=<id>#block-<blockId>` para a área de transferência.

### 4.2 Menu de comando "/"

Digitar `/` em qualquer ponto do texto abre um menu filtrável por título/descrição, agrupado em:

- **Texto**: Texto, Título 1, Título 2, Título 3, Citação
- **Lista**: Lista com marcadores, Lista numerada, Lista de tarefas
- **Mídia**: Imagem (abre seletor de arquivo e faz upload), Arquivo, Preview de link (pede uma URL e busca metadados)
- **Avançado**: Callout, Bloco de código, **Alternador (toggle)**, Tabela (insere 3×3 com cabeçalho), Divisor, **2 Colunas**, **3 Colunas**
- **Inline**: Menção, Emoji

O mesmo menu também é aberto pelo botão "+" do controle lateral de blocos (ver 4.3), mesmo sem o caractere `/` ter sido digitado.

### 4.3 Controles à esquerda de cada bloco ("+" e alça de arraste)

Ao passar o mouse sobre um bloco, aparecem dois controles flutuantes à esquerda — **em qualquer profundidade**: um parágrafo dentro de uma coluna, um item de lista ou o corpo de um alternador (toggle) mostra seus próprios controles, não mais os do bloco pai inteiro (resolução por profundidade arbitrária, `resolveActiveBlock`/`resolveActiveBlockAt` em `NotionStyleEditor.vue` — ver `docs/PLANO_EDITOR_P1.md`, Parte 5):

- **"+"** — insere um novo parágrafo vazio logo após o bloco e abre o menu de inserção nesse ponto.
- **Alça de arraste (⠿)** — gatilho de um menu com ações, todas funcionando em qualquer profundidade:
  - Mover para cima / para baixo — reordena entre os irmãos reais do bloco (dentro do mesmo container: coluna, item de lista, corpo do toggle, ou a raiz do documento), nunca "vaza" para fora dele.
  - Converter em: Texto, H1, H2, H3, Lista com marcadores, Lista de tarefas
  - Duplicar, Copiar texto, Copiar link do bloco
  - Excluir bloco — se for o único filho de um container (coluna/item de lista/corpo do toggle), limpa o conteúdo em vez de remover o nó (o schema exige pelo menos um bloco filho ali).

> ⚠️ O **arrasto pelo mouse** (segurar a alça e soltar em outro lugar) continua funcionando só para blocos de **nível superior** — generalizar o gesto de arrastar (e a criação de colunas arrastando) para qualquer profundidade ficou de fora desta fase de propósito (ver seção 11).

### 4.4 Arrastar e soltar blocos, criação de colunas

O reordenamento usa uma implementação própria (não o drag nativo do ProseMirror), com um tipo MIME dedicado. Ao arrastar um bloco sobre outro:

- Se o ponteiro estiver sobre a **faixa central** do bloco alvo, aparece uma linha horizontal indicando que o bloco será **reordenado** para aquela posição.
- Se o ponteiro estiver sobre as **bordas laterais** (os ~30% mais à esquerda ou mais à direita do bloco), aparece um indicador vertical: soltar ali **cria um layout de colunas**, envolvendo o bloco de origem e o de destino em um novo bloco `columns` com duas colunas de 50%/50%. É assim que se cria um layout multi-coluna ad-hoc, arrastando um bloco sobre o outro (além dos itens "2 Colunas"/"3 Colunas" do menu "/").

### 4.5 Layout de colunas

Cada coluna tem:
- Um botão "⋯" (canto superior direito, só no modo edição) com as ações **Coluna à esquerda** / **Coluna à direita** (insere nova coluna, redistribuindo as larguras) e **Excluir coluna** — ao restar apenas 2 colunas e uma delas ser excluída, o bloco `columns` é desfeito e os blocos da coluna remanescente voltam para o documento principal.
- Uma **alça de redimensionamento** entre colunas adjacentes (arrastar altera a largura em %, com mínimo de 120px por coluna).
- Placeholder "Pressione '/' para adicionar conteúdo" em colunas vazias.

> Hoje as ações da coluna ficam num menu à direita — o padrão Notion (ações no lado esquerdo, junto ao bloco) ainda está pendente de implementação (ver seção 11).

### 4.6 Formatação de texto selecionado (menu de seleção / bubble menu)

Ao selecionar texto, aparece um menu flutuante acima da seleção com:

- Indicador/seletor do tipo de bloco atual (abre a visão "Converter em").
- Marcas: **Negrito, Itálico, Sublinhado, Tachado, Código inline, Cor do texto, Destaque**.
- **Cor do texto / Destaque**: abrem uma view própria com paleta fixa de 9 cores (padrão Notion: cinza, marrom, laranja, amarelo, verde, azul, roxo, rosa, vermelho) + opção "Padrão" que limpa a cor.
- **Link** (campo de URL inline, com prefixo automático `https://` e opção de remover o link).
- **Limpar formatação**.
- **Alinhamento**: esquerda, centro, direita, justificado.

A visão "Converter em" permite trocar o bloco selecionado para: Texto, H1, H2, H3, Lista com marcadores, Lista numerada, Citação ou Bloco de código.

### 4.7 Barra de ferramentas de tabela

Quando o cursor está dentro de uma tabela, uma barra fixa oferece: inserir linha acima/abaixo, excluir linha, inserir coluna à esquerda/direita, excluir coluna, alternar linha de cabeçalho, excluir tabela.

### 4.8 Vínculos entre notas (wikilinks e menções)

Existem dois mecanismos paralelos para linkar notas, e ambos alimentam o mesmo grafo de conhecimento:

1. **Autocomplete `[[`**: ao digitar `[[`, um menu próprio (não é o `Suggestion` padrão do Tiptap) filtra as notas disponíveis pelo título (até 8 resultados, excluindo a nota atual). Selecionar uma opção insere um nó `[[Título]]` clicável.
2. **Arrastar uma nota da barra lateral** para dentro do editor também insere um wikilink diretamente.
3. **Menção `@`**: menu mais genérico (acessível pelo "/" → Menção), que por padrão lista as notas disponíveis, mas também aceita texto livre ("menção manual") quando não há correspondência. Uma menção do tipo nota (`@Título`) é visualmente diferente do wikilink (`[[Título]]`), mas tem o mesmo efeito de vínculo.
4. Clicar num wikilink renderizado navega diretamente para a nota referenciada.
5. **Sincronização automática de vínculos ao salvar**: a cada salvamento, o editor varre o conteúdo salvo em busca de nós `wikilink` e de menções do tipo nota, compara com os vínculos já existentes da nota (buscados da API) e cria/remove vínculos (`note_links`) conforme necessário. É esse mecanismo que alimenta a visão de Grafo e a contagem de backlinks — não existe uma ação manual separada de "criar vínculo".

### 4.9 Salvamento automático

Não há salvamento a cada tecla digitada. O editor rastreia se há alterações pendentes (`dirty`) e exibe um indicador de status: **Não salvo** (ponto âmbar), **Salvo às HH:MM** (check verde), **Erro — Tentar novamente** (vermelho, clicável) ou a data da última edição.

- Uma verificação roda a cada 10 segundos; se houver alterações pendentes e tiverem se passado ao menos 60 segundos desde a última edição, a nota é salva.
- Também é forçado o salvamento ao: fechar/trocar de componente, sair da rota, navegar para outra nota, ou ao desfocar o campo de título.
- O salvamento (assim como toda outra escrita do módulo) passa pelo "gerenciador" de ações otimistas — ver seção 12.

### 4.10 Upload de imagens e arquivos

- Arrastar-e-soltar ou colar do clipboard também disparam upload.
- Barra de progresso por arquivo, com opção de cancelar/tentar novamente/dispensar.
- Validações no servidor: bloqueio de extensões/MIME types perigosos (executáveis, scripts, SVG), lista de imagens permitidas (PNG/JPEG/WEBP/GIF), limites de tamanho configuráveis.
- **Limpeza de órfãos**: se uma imagem/arquivo é removido do documento, o arquivo correspondente no storage é apagado automaticamente após 30 segundos (a menos que reapareça nesse intervalo, por exemplo via "desfazer").
- O bloco de imagem permite escolher largura (50%/75%/100%), adicionar legenda e substituir o arquivo.

### 4.11 Preview de link

Ao inserir um "Preview de link", o servidor busca a URL (com proteção contra SSRF — bloqueia IPs privados/localhost), extrai metadados Open Graph (título, descrição, imagem, nome do site) com cache de 1 hora, e monta um cartão rico no documento.

### 4.12 Atalhos de markdown

Apenas os atalhos padrão do `StarterKit` do Tiptap funcionam hoje (ex.: `#`/`##` para título, `-`/`*` para lista, `1.` para lista numerada, `>` para citação, `` ``` `` para bloco de código, `---` para divisor). Não há atalhos de markdown customizados adicionais implementados.

## 7. Busca (`SearchDialog.vue`)

Modal de busca no estilo "Cmd+K" (Notion/Obsidian), aberto pelo botão de busca da barra lateral (sem atalho de teclado dedicado até o momento):

- **Sem termo digitado**: lista todas as notas (fixadas primeiro, depois por data de atualização), agrupadas por período relativo — Hoje / Ontem / Últimos 30 dias / Anteriores.
- **Com termo digitado**: usa resultados vindos do servidor (busca com debounce de 300ms), com um trecho de contexto (excerpt) recortado ao redor do termo encontrado.
- **Filtros disponíveis**: alternância "Título" (restringe a busca ao título), dropdown de **Pasta**, dropdown de **período** (Qualquer data / Hoje / Últimos 7 dias / Últimos 30 dias). Existe também um filtro "Você" já desenhado na interface, mas desabilitado — provável preparação para um filtro de autor/colaborador futuro.
- Cada resultado mostra ícone colorido do tipo, título, pasta (se houver) e o trecho de contexto.

A busca no servidor usa correspondência simples (`ilike`) sobre título e conteúdo bruto — não é uma busca full-text estruturada sobre o conteúdo do editor, mas funciona porque o conteúdo é armazenado como JSON serializado (o termo é encontrado mesmo dentro da estrutura). Ver `docs/ANALISE_EDITOR_MERCADO.md` (seção 6.1) sobre por que vale migrar isso para full-text search antes que o volume de notas cresça.

## 8. Visualização em Grafo (`GraphView.vue`)

Grafo de conhecimento renderizado em `<canvas>`, com física própria (sem biblioteca externa):

- **Nós** = todas as notas do usuário; o tamanho do nó cresce com a quantidade de vínculos (`linkCount`).
- **Arestas** = os vínculos (`note_links`) originados por wikilinks e menções do tipo nota.
- Cor por tipo de nota: Nota (índigo), Ideia (amarelo), Conceito (ciano), Pesquisa (verde), Nota de livro (cinza) — legenda exibida no canto inferior esquerdo.
- **Simulação física**: repulsão entre nós, atração ao longo das arestas, leve atração ao centro, amortecimento de velocidade — roda por até 300 quadros após qualquer mudança nos dados e então se estabiliza. As posições dos nós já existentes são preservadas entre atualizações, para o layout não "pular" ao criar um novo vínculo.
- **Interações**: arrastar um nó reposiciona-o; arrastar o fundo faz pan; roda do mouse dá zoom (0.2×–5×) centrado no cursor; passar o mouse destaca o nó; clicar em um nó navega para a nota correspondente no editor. Botões de reset de visão, zoom in/out.
- Estados de carregamento e vazio ("Crie notas e vínculos para visualizar o grafo") tratados.
- **Sem filtros**: hoje o grafo sempre mostra todas as notas e vínculos do usuário — não há filtro por tipo, tag ou pasta.

| --- | --- | --- |

| `note_tags` | `id, user_id, name, color, created_at` | RLS restrita ao dono |
| `note_tag_links` | `note_id, tag_id` (PK composta) | Tabela de junção nota↔tag |

O conteúdo (`notes.content`) é armazenado como o **JSON do documento Tiptap**. Conteúdo salvo como texto puro (ex.: pelo modal de criação) é tratado como fallback legado e envolvido em um único parágrafo ao ser aberto no editor.

## 12. O "gerenciador" de ações otimistas (`useNotes.ts`)

Toda ação de escrita do módulo — criar, editar, excluir, mover, fixar/desfixar, reordenar, criar/renomear/excluir pasta e tag, expandir/recolher pasta, vincular/desvincular notas — segue o mesmo padrão de **UI otimista**: a interface reflete a ação **imediatamente**, sem esperar a resposta do backend, e desfaz automaticamente com um toast de erro caso o servidor rejeite a operação.

**Exceção — ações da Lixeira** (`fetchTrash`, `restoreNote`, `restoreFolder`, `permanentlyDeleteNote`, `permanentlyDeleteFolder`): não passam por `runOptimisticAction`. `restoreNote`/`permanentlyDeleteNote` fazem a chamada e só então atualizam o store local (a UI não "adivinha" o resultado antes da resposta); `restoreFolder`/`permanentlyDeleteFolder` disparam um refetch completo (`refreshFolders`/`refreshAllNotes`/`refreshNotes`/`fetchTrash`) em vez de patch local, porque a operação é recursiva e afeta um conjunto de itens que não dá pra saber de antemão sem consultar o servidor.

### Store local reativo

`app/composables/useNotes.ts` mantém três `Map`s reativos como fonte única de verdade da UI:

```ts
const notesById = reactive(new Map<string, Note>())
const foldersById = reactive(new Map<string, NoteFolder>())
const tagsById = reactive(new Map<string, NoteTag>())
```

Populados inicialmente pelos mesmos `useFetch` de sempre (`/api/notes`, `/api/notes/folders`, `/api/notes/tags`), mas a partir daí toda leitura da UI (`NotesList`, `SearchDialog`, etc.) deriva desses Maps via `computed`, e toda escrita muta o Map diretamente — sem depender de um novo fetch para a UI reagir.

### Helper genérico (`app/composables/useOptimisticAction.ts`)

```ts
interface OptimisticActionOptions<T> {
  apply: () => void                // muda o store local, síncrono, antes de qualquer rede
  rollback: () => void             // reverte o store se a request falhar
  request: () => Promise<T>        // a chamada real ao backend
  reconcile?: (result: T) => void  // aplica a verdade do servidor (ids, timestamps) após sucesso
  errorMessage: string
  silent?: boolean                 // suprime o toast de erro (ações de baixo risco/alta frequência)
}
```

`apply()` roda **antes** do `await` da requisição — é isso que faz a ação parecer instantânea. Em caso de erro, `rollback()` desfaz e um toast avisa o usuário (a menos que `silent`); em caso de sucesso, `reconcile()` substitui os dados otimistas pela resposta real do servidor (por exemplo, trocando o ID temporário de uma nota recém-criada pelo ID definitivo).

### Casos especiais

- **Criação**: usa um ID temporário (`temp-<uuid>`) até a resposta do servidor chegar; nenhum lugar do app precisa tratar esse ID especialmente porque tudo trabalha com o objeto reativo, não com o ID cru — a única exceção seria algo que persistisse o ID fora do store (o histórico de navegação, por exemplo), mas como todos os pontos de criação no app aguardam (`await`) a resposta antes de navegar, isso não chega a ser um problema na prática.
- **Exclusão de pasta em cascata**: calcula localmente (a partir da árvore já carregada) todas as subpastas e notas afetadas, remove tudo otimisticamente numa única operação, e desfaz tudo junto em caso de erro.
- **Reordenar (posição customizada)**: usa indexação fracionária — a nova posição de um item é a média entre as posições dos vizinhos onde foi solto, então só o item movido precisa ser escrito (não a lista inteira).
- **Expandir/recolher pasta**: aplica local instantaneamente, mas a escrita no backend é debounced (400ms) por pasta, já que é uma ação de clique frequente.
- **Grafo**: não participa do store otimista — é atualizado em segundo plano (`refreshGraph`, sem bloquear a UI) depois de ações que afetam vínculos.
